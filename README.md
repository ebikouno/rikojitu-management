# rikojitu-management

Instagram アカウント **@riko_jitu**（3人運営）の分析・リサーチ・台本作成・情報管理を、Claude Code の 4 部門（サブエージェント）で回すためのリポジトリです。

## 組織図

```
                    オーナー（あなた）
                          │ 指示・承認
                          ▼
        ┌──────────────────────────────────────┐
        │ 4. リーダー兼秘書 / プラットフォーム管理 │  ← メインセッション（CLAUDE.md）
        └──────────────────────────────────────┘
             │ 指示            │ 指示            │ 指示
             ▼                 ▼                 ▼
   1. 競合・トレンド分析   2. 自アカウント分析    3. 台本作成
   (trend-researcher)     (insights-analyst)    (script-writer)
             │                 │                 │
             └──── 結果を Google Drive プラットフォームに記入 ────┘
```

| # | 部門 | エージェント定義 | 役割の要点 |
|---|------|------------------|------------|
| 1 | 競合・トレンド分析部門 | `.claude/agents/trend-researcher.md` | プラットフォームの競合リスト・ペルソナ・方針に沿って外部調査。ネタ候補を記入 |
| 2 | 自身のInstagram分析部門 | `.claude/agents/insights-analyst.md` | @riko_jitu のインサイト分析・方針変更の**提案**（変更の実行はしない） |
| 3 | 台本作成部門 | `.claude/agents/script-writer.md` | 過去台本＋分析結果から台本作成。**オーナー承認後のみ**プラットフォームに記入 |
| 4 | リーダー兼秘書・プラットフォーム管理 | `CLAUDE.md`（メイン）/ `.claude/agents/leader-secretary.md` | プラットフォーム作成・管理、3部門への指示・取りまとめ、オーナーの秘書 |

## 使い方

このリポジトリを Claude Code で開き、普段どおり話しかけるだけです。メインセッションがリーダー兼秘書として動き、必要に応じて各部門を呼び出します。

例:
- 「今週の定例分析を回して」→ 部門2 → 部門1 → リーダーが週次レポートを作成
- 「競合の @xxx を調べて次のネタを5個」→ 部門1
- 「来週投稿用の台本を3本」→ 部門3 が作成 → あなたに採否確認 → 採用分のみ記入
- 「Aさんの意見をプラットフォームにまとめて」→ リーダーが記入

## ディレクトリ

```
.claude/agents/        各部門のエージェント定義
departments/           各部門の業務マニュアル（手順・出力形式）
templates/             レポート・台本などの記入テンプレート
docs/workflow.md       定期実行・連携フロー
docs/open-decisions.md 作業開始前に決めるべきこと
```

## 守るルール（全部門共通）
- Instagram アカウントへの投稿・編集・削除など **アカウントへの変更は一切行わない**。
- 台本はオーナー承認前にプラットフォームの「採用台本」へ記入しない。
- 推測と事実（データ）を区別して書く。データの取得日・取得元を必ず残す。
