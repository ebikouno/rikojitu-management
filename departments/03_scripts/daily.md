## 手順
1. 読む
   - `docs/drafts/series-tracker.md`（次に作る回・次の台本ID・回し方）
   - `docs/data/past_scripts.json`（過去台本37本。続編は主にこれを参考にし、シリーズの型・セリフ回しを崩さない）
   - `docs/data/insights_2026-10-20.json`（全94本の成績）と `docs/drafts/` の過去の台本案（ネタの重複を避ける）
   - `docs/reference/persona-guide-2026-10-20.md`（方針・ペルソナ・制作ルール）、`templates/script.md`
   - `docs/drafts/ron-edit-notes.md`（ろんの直しの傾向）。**必ず反映する。**
   - 落書き帳（1JLp76hT-MaA15xGMOPG_jDMSpJAz7qk7gOdF-xrNBFI）と台本ノート（1zT9BE9tOdKbExobNzQXmI-5zBNLNDOJgJJnWx1XmiM4）の両方を読み、ろんが新しく直した台本（コメント欄に「編集済み」など）や、落書き帳から台本ノートに移された台本を、`docs/drafts/` の元の案と比べる。新しい傾向やコメントがあれば `ron-edit-notes.md` に日付つきで追記する。ろんが「採用」「見送り」などに変えた台本も把握する。
2. 書く: `docs/drafts/YYYY-MM-DD_台本案.md`（形式は `docs/drafts/2026-10-20_台本案.md` と同じ。タイトル／種別／第一ペルソナと理由／フック案2〜3／本文（役：セリフ（動き）【テロップ】、30〜40秒）／オチ／撮影メモ／キャプション案／採点4項目／見たい指標）。作成者表記は「ろん」。
3. 更新: `docs/drafts/series-tracker.md` の「台本済みの最新」「次に作る回」「次の台本ID」「作成ログ」。
4. commit して push（まず `git push origin HEAD:main`、拒否されたら `git push -u origin HEAD`。ブランチに入った分は管理セッションが main にまとめる）。
5. ろんに通知:
   - **Gmail で確認を依頼する**（宛先: ろん ebizukakounosuke@gmail.com のみ、件名「【確認依頼】台本案 YYYY-MM-DD S-xxx〜S-xxx」）。本文：冒頭に結論（落書き帳に書いたこと・確認してほしいこと）→ 落書き帳のリンク https://docs.google.com/document/d/1JLp76hT-MaA15xGMOPG_jDMSpJAz7qk7gOdF-xrNBFI/edit → 3本の一覧（ID・タイトル・種別・誰向け・採点）→ 3本それぞれの本文 → 今回反映したろんの直しの傾向 → 判断してほしい点（番号付き）→「確認したら、落書き帳のコメント欄に直しや採否を書くか、よいものは台本ノートに移してください」。前日以前の台本でまだ確認されていないもの（落書き帳でコメント欄が空のもの）があれば、末尾に一覧で再度お願いする。
   - セッションの最終報告にも同じ内容を書く（プッシュ通知が届く）。
6. **落書き帳に自動で書き込む**（手順4の後、手順5の前）:
   - 「▼ ここから下に台本案（新しいものを上に）」の直後に、見出し「【台本案 S-xxx〜S-xxx】ろん YYYY-MM-DD」で3本を追記（形式は台本ノートの台本と同じ。各本の最後に「コメント：」欄）。ろんやメンバーが書いた既存の内容は書き換えない・消さない。
   - 台本ノートとアイデア帳には自動で書き込まない。ろんが落書き帳から台本ノートに移した台本は、週次ノート反映でアイデア帳に転記する。
