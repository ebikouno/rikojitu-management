1. 読む

   - `docs/reference/persona-guide-2026-10-20.md`（方針・ペルソナ・制作ルール）、`templates/script.md`
   - `docs/drafts/ron-edit-notes.md`（ろんの直しの傾向）。**必ず反映する。**

2. 書く: `docs/drafts/YYYY-MM-DD_台本案.md`（形式は `docs/drafts/2026-10-20_台本案.md` と同じ。タイトル／種別／第一ペルソナと理由／フック案2〜3／本文（役：セリフ（動き）【テロップ】、30〜40秒）／オチ／撮影メモ／キャプション案／採点4項目／見たい指標）。作成者表記は「ろん」。
3. 更新: `docs/drafts/series-tracker.md` の「台本済みの最新」「次に作る回」「次の台本ID」「作成ログ」。
4. commit して push（まず `git push origin HEAD:main`、拒否されたら `git push -u origin HEAD`。ブランチに入った分は管理セッションが main にまとめる）。
5. ろんに通知:
   - **Gmail で確認を依頼する**（宛先: ろん ebizukakounosuke@gmail.com のみ、件名「【確認依頼】台本案 YYYY-MM-DD S-xxx〜S-xxx」）。本文：冒頭に結論（台本ノートに上げたこと・確認してほしいこと）→ 台本ノートのリンク https://docs.google.com/document/d/1zT9BE9tOdKbExobNzQXmI-5zBNLNDOJgJJnWx1XmiM4/edit → 3本の一覧（ID・タイトル・種別・誰向け・採点）→ 3本それぞれの本文 → 今回反映したろんの直しの傾向 → 判断してほしい点（番号付き）→「確認したら、台本ノートのコメント欄に『編集済み』や採否を書いてください」。前日以前の台本でまだ確認されていないもの（コメント欄が空のもの）があれば、末尾に一覧で再度お願いする。
   - セッションの最終報告にも同じ内容を書く（プッシュ通知が届く）。
6. **Drive に自動で上げる**（手順4の後、手順5の前）:
   - 台本ノート：「▼ ここから下に台本を書く（新しいものを上に）」の直後に、見出し「【台本案 S-xxx〜S-xxx】ろん YYYY-MM-DD（管理用シートに反映済み）」で3本を追記（形式は 2026-10-23 の S-007〜S-009 と同じ。各本の最後に「コメント：」欄）。ろんやメンバーが書いた既存の内容は書き換えない・消さない。
   - アイデア帳「台本案を書く」（1mNsV1kE1-fHo_qEoMDCJ3RGAy-obFTwWYc2mJEXcMsc）：空いている次の行に1本1行で追加。ステータス「承認待ち」、コメント欄「ろん確認待ち（台本ノートに掲載 YYYY-MM-DD）」、合計点の列は自動計算なので書かない。
