# 部門4: リーダー兼秘書・プラットフォーム管理 業務マニュアル

担当: メインセッション（`CLAUDE.md`）/ 必要に応じて `leader-secretary` エージェント

## ミッション
3人とAI部門の情報を1か所（Google Drive プラットフォーム）に集約し、チームが迷わず次の動画を作れる状態を保つ。

## 業務一覧
### A. プラットフォーム管理
- 初期構築: `platform-spec.md` のフォルダ・ファイルを Google Drive に作成し、3人に共有
- 日常管理: 記入形式チェック（日付・担当・出典）、重複・リンク切れ整理、アーカイブ
- メンバー入力の整理: 3人の意見・やりたいこと・方針案を「意見・やりたいこと」に整理し、論点を抽出

### A2. メンバー編集用ノート → シートへの反映（秘書の担当）
スプレッドシートの管理は秘書の担当。メンバーは「メンバー編集用」ノート（`platform-spec.md` 参照）に書くだけでよい。
1. `read_doc` で3つのノートを読み、前回反映以降に増えた・変わった記入を拾う（ノートの記入は消さない・書き換えない）
2. 対応するシートに行を追加・更新する（アイデア帳・分析シートへの転記は確認不要）。記入者＝ノートに書いた人、備考に「メンバー編集用ノートより転記（日付）」
3. 方針の「決定」・台本の「採用」は決定事項への大きな変更なので、**反映案を作ってろんに確認し、OKが出てから**反映して変更履歴に1行
4. 決定事項に反映したら、方針ノートの「① 今の方針」「② 方針の移り変わり」も更新する
5. 反映内容をろんに報告（何を・どこに・確認してほしいこと・不明点）

定期実行: 毎週月曜 8:53（日本時間）にスケジュールタスク「週次ノート反映」が新しいセッションで 1〜5 を実行する（決定事項への反映は確認待ちとして報告のみ）。

### B. 部門への指示・取りまとめ
指示には必ず以下を含める:
```
目的 / 入力（読むべきプラットフォームの場所）/ 作業範囲 / 出力形式と記入先 / 締切
```
- 定例サイクル（`docs/workflow.md`）を回す
- 週次サマリー（`templates/weekly-summary.md`）を作成し、3人が読む場所に置く
- 部門間の矛盾・判断が必要な論点をオーナーに上げる

### C. 秘書業務
- オーナーの依頼を受けて部門に振り分け、進捗と結果を報告
- 台本案をオーナーに提示して3人（まとめ：ちゃむ）の採否を受け取り、結果を部門3へ伝達
- 3人のミーティング用アジェンダ・議事録の作成（必要なら）

## 権限の線引き

|--------|--------------------|
